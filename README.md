# sema-agent — житель машины для Сёмы

## In English

`sema-agent` is a companion daemon for [Sema](https://github.com/PavluninVladimir/sema),
a self-hosted personal assistant. Sema itself usually lives in a container or
on another box; this agent runs on the machine where your files are and does
what cannot be done remotely:

- **code understanding** through language servers (gopls, rust-analyzer,
  typescript-language-server and others) — compact symbol cards instead of whole files;
- **a memory door for coding agents** — MCP over stdio plus memory hooks for
  Claude Code and Codex, talking to Sema over its own mutually authenticated TLS link;
- **desktop notifications** and a menu bar icon on macOS.

The agent only reads: it never edits files or runs commands. The interface,
logs and documentation are in Russian.

```sh
make build                                              # versioned build
./semaagent -enroll <code> -sema http://sema.local:8765 # one-time enrollment, code from Sema's "Agents" screen
./semaagent -link sema.local:8766                       # daemon: link to Sema + local socket
```

## По-русски

### Что это и зачем

Сёма живёт в контейнере или на отдельной машине и переезжает вместе с ней.
Файлы репозиториев, языковые серверы и рабочий стол остаются здесь, на машине
человека. **Житель машины** (`semaagent`) делает на месте то, чего нельзя
сделать издалека, и говорит с Сёмой своим шифрованным проводом.

Это отдельный проект: он ставится на любую машину, где работают агенты
разработки, и от кода Сёмы не зависит. Связь — только протокол.

**Агент только читает**: файлов не правит, команд не запускает.

### Роли

У экземпляра одна роль, и роли не совмещаются:

- **житель** — читает репозитории человека, держит языковые серверы,
  дверь в память и уведомления;
- **шлюз** — лицо Сёмы в интернете: принимает браузеры снаружи и передаёт
  их домой тем же проводом. Это другой экземпляр со своей учётной записью и
  своим удостоверением.

Роль выбирает человек в Сёме, когда выдаёт одноразовый код, и закрепляет её
Сёма, а не сертификат: сертификат перевыпускается по сроку. Смены роли нет —
это другой экземпляр. Какие способности положены роли, решает одно место —
`roleCapabilities` в `cmd/semaagent/role.go`. Способность не из списка Сёме не
объявляется, и отказ пишется в журнал с причиной.

### Способности

- **Код** — пул языковых серверов и карточки вместо содержимого файлов.
- **Память** — единственная дверь в память Сёмы для агентов разработки.
  Сёма пересоздаётся при каждом обновлении контейнера, а житель стоит службой
  и переживает это: провод рвётся, житель перезванивает и повторяет вопрос сам.
- **Уведомления** — значок у часов и системные уведомления (только macOS).

Способности объявляет агент, а разрешает человек поимённо на экране
«Агенты» в Сёме. Новая способность приходит выключенной; отзыв агента
действует немедленно.

### Инструменты MCP

Двенадцать инструментов. Про код — семь:

| Инструмент | Что делает |
|---|---|
| `symbols` | оглавление файла |
| `context` | карточка символа: объявление, где используется |
| `impact` | радиус поражения перед правкой |
| `definition` | где объявлено |
| `diagnostics` | что сломано сейчас, без сборки; с `text` проверяется код, которого нет на диске |
| `search` | поиск по коду |
| `agent_status` | какие языки готовы, какие серверы подняты |

Про память — пять: `memory_session_start`, `memory_session_end`,
`memory_recall`, `memory_remember`, `code_knowledge`. Память спрашивается у
Сёмы по проводу, и рабочая папка едет в каждом запросе: житель один, а
проектов много, и области памяти выдаются паре «агент разработки плюс папка».
Обрыв провода — ошибка про связь, а не пустой ответ: пустоту агент
разработки прочитал бы как «в памяти ничего нет».

Карточки `symbols` и `context` несут раздел «Что здесь известно» из памяти
Сёмы: места карточки (папка, файл, символы) уходят одним запросом. Ждём не
дольше `-knowledge-ms` (800 мс); истёк срок или нет провода — карточка
уходит сразу с пометкой «память недоступна».

### Ярусы ответа

Каждый ответ помечен ярусом первой строкой карточки — клиент, не знающий
точности ответа, будет уверенно ошибаться:

- `lsp` — ответил языковой сервер;
- `tags` — оглавление по universal-ctags (системный ctags из Xcode не годится
  и распознаётся по `--version`);
- `text` — совпадения по слову через ripgrep (без него — обычный `grep`).

Нет сервера языка — ответ ярусом ниже с честной пометкой. Нет и утилит —
честный отказ. У диагностики ярусов ниже нет: молчание — не «замечаний нет».

Языки берутся из реестра по расширению: Go (`gopls`), Rust
(`rust-analyzer`), Swift (`sourcekit-lsp`), TypeScript и JavaScript
(`typescript-language-server`), Python (`pyright-langserver`), Vue
(`vue-language-server`). Сервер стартует лениво и гасится после тишины
(`-idle`, 20 минут); одновременно живут не больше `-max` серверов (3).

### Связь с Сёмой

- У Сёмы свой удостоверяющий центр (Ed25519). Агент входит одноразовым
  кодом с экрана «Агенты» (`-enroll`), получает свой сертификат и корень.
- Дальше **звонит агент**, а не Сёма: ноутбук спит, меняет сеть и стоит за
  домашним роутером. TLS 1.3 со взаимной проверкой, адрес — `-link`
  (порт 8766 по умолчанию у Сёмы).
- По одному соединению идёт JSON-RPC в обе стороны: Сёма зовёт
  `код.<умение>`, агент зовёт `память.<инструмент>`. Пинг раз в две минуты,
  обрыв — переподключение с растущей паузой; пауза сбрасывается, если
  соединение прожило дольше минуты.
- Сменившийся отпечаток при знакомом имени — тревога в Сёме, а не тихое
  переподключение.

### Местная дверь: демон и обёртка

Демон — тот, кто держит провод (`-link`). Он же открывает местную дверь:
сокет `~/.sema-agent/agent.sock` с правами 0600. Агенты разработки
запускают тот же бинарник без флагов; он видит живого демона и работает
тонкой обёрткой, поэтому языковой сервер поднимается один раз на всех.
Ни адреса Сёмы, ни токена в настройках агентов разработки нет.

Сетевого рта у жителя нет вовсе: только stdio и сокет в домашней папке.

### Сборка

```sh
make build        # ./semaagent с версией
make linux        # dist/semaagent-linux-amd64 и -arm64
make mac          # dist/semaagent-darwin-<arch>
make test         # go test ./...
make vet          # go vet ./...
```

Собирать через `make`, а не `go build` руками: версию подставляет линковщик
(`-X main.Version=…`), и без неё агент назовёт Сёме «dev» — обновление
станет невидимым. Сборка без cgo, бинарник кросс-компилируется: на целевой
машине не нужны ни Go, ни исходники.

### Флаги

| Флаг | Что задаёт |
|---|---|
| `-enroll <код>` | разовый вход по приглашению: получить удостоверение и выйти |
| `-role житель\|шлюз` | роль, которую агент просит при входе (главное слово — за Сёмой) |
| `-sema <адрес>` | адрес Сёмы для входа по приглашению, например `http://sema.local:8765` |
| `-link <хост:порт>` | адрес провода к Сёме, например `sema.local:8766`; делает процесс демоном |
| `-home <папка>` | где лежит удостоверение, по умолчанию `~/.sema-agent` |
| `-hook <вид>` | хук памяти: `session-start`, `note`, `session-end`, `subagent-note`; событие на stdin |
| `-agent <имя>` | кто спрашивает память: `Claude Code`, `Codex` |
| `-max`, `-idle` | сколько языковых серверов держать и через сколько минут тишины гасить |
| `-knowledge-ms` | сколько карточка ждёт раздел из памяти |
| `-gate-sema`, `-gate-http`, `-gate-domain`, `-gate-acme` | только для роли «шлюз», см. `deploy/README.md` |

### Установка

Порядок один на все системы: положить бинарник, поставить службу, ввести
одноразовый код, убедиться, что агент виден Сёме на экране «Агенты».
Подробно — `deploy/README.md`.

**macOS** — служба `launchd`:

```sh
./deploy/install-mac.sh sema.local:8766
```

Скрипт собирает бинарник, кладёт его в `~/.local/bin`, разворачивает шаблон
`deploy/semaagent.plist` с настоящими путями и перезагружает службу. Метка
службы — `SEMA_AGENT_LABEL`, по умолчанию `org.example.semaagent`; служба
жителя, поставленная раньше под другой меткой, снимается, чтобы их не было
две. Перезапуск: `launchctl kickstart -k gui/$UID/org.example.semaagent`.

**Linux** — `systemd` в двух видах:

- `deploy/semaagent.user.service` — служба человека (`systemctl --user`) на
  личной машине: житель видит репозитории и сокет в домашней папке;
- `deploy/semaagent.service` — служба системы от своего пользователя на
  общей машине: удостоверение не лежит в чужом домашнем каталоге, но и
  репозиториев человека агент не видит.

Обновление — замена бинарника и перезапуск службы. Удостоверение, роль и
разрешённые способности лежат в каталоге состояния и замену переживают.
Бинарник кладётся рядом и переименовывается (`install`, `mv`), а не
копируется поверх: живой процесс держит файл, и `cp` даст «text file busy».

PATH службы урезан, а житель ищет на диске языковые серверы, `ctags`,
`ripgrep` и `swiftc`. Поэтому PATH задан в файлах службы явно и включает
`~/go/bin` (там `gopls`). Проверка — `agent_status`: у языка должно стоять
«готов», а не «нет сервера».

### Подключение к агентам разработки

Готовые примеры — в `integrations/`.

**Claude Code.** Сервер MCP — сам бинарник:
`mcpServers.sema-agent.command = <путь к semaagent>`. Хуки памяти —
`integrations/claude-code/settings.example.json` (пути поправить на свои):
`SessionStart` кладёт в контекст уроки, факты и итог прошлой сессии
проекта, `Stop` дописывает последний обмен репликами, `SubagentStop` —
итог субагента (иначе его работа идёт мимо памяти), `SessionEnd` закрывает
сессию.

**Codex.** Сервер MCP — `integrations/codex/config.example.toml`. Хуки:

```sh
codex features enable hooks
# ~/.codex/hooks.json — по образцу integrations/codex/hooks.example.json
```

После любой правки `hooks.json` — `/hooks` в консольном Codex и «trust»:
изменённый хук молча пропускается, пока его не доверили, без ошибки и без
строки в журнале. Разовый `codex exec` хуков не зовёт вовсе — для него
обёртка `integrations/codex/exec.sh «задание» [папка]`: сама открывает
сессию, подмешивает память проекта, кладёт ответ заметкой и закрывает
сессию даже при неудаче. В неинтерактивном `codex exec` вызовы MCP по
умолчанию требуют подтверждения — запускать с `--approve-for-me`.

Каждый хук — одна строка `semaagent -hook <вид>`: разбор события, поиск
корня проекта и разговор с Сёмой живут в бинарнике. Хук всегда
завершается с нулевым кодом — сессия агента разработки не должна падать
из-за памяти. Нет жителя — хук молчит.

**Корень работы** — git-корень; если у родителя лежит `CLAUDE.md`, а своего
`.git` нет, корнем считается родитель: несколько репозиториев в одной
папке — один проект. Абзацы такого `CLAUDE.md` с жирным заголовком и
путями в обратных кавычках житель разбирает в «принципы» и отправляет Сёме
при старте сессии, если файл изменился; Сёма хранит их привязками к
папкам и файлам.

**Мост к Codex** (`integrations/codex-bridge`) — необязательный: делает
`codex exec` видимым Сёме как OpenAI-совместимую модель (например, вторая
голова для суда над командами). Требует токен в заголовке и зовёт Codex
только на чтение.

### Чего на Linux нет

Значок у часов, помощник на Swift и `osascript` — это Cocoa. На Linux агент
говорит об этом строкой в журнале при старте и работает дальше, а
способность «уведомления» не объявляет вовсе: обещать Сёме доставку,
которой не будет, хуже, чем её не обещать. Карточки кода, память и хуки
работают одинаково; тегов сборки нет, код один.

На macOS значок рисует помощник на Swift — бандл с `LSUIElement`, который
агент собирает на месте (`swiftc`, ad-hoc подпись, `lsregister -f`) и держит
своим потомком; сам агент остаётся Go без cgo. Нет `swiftc` — уведомления
идут через `osascript`, значка нет, и это сказано в журнале.

### Где лежит состояние

Каталог `~/.sema-agent` (права 0700):

| Файл | Что в нём |
|---|---|
| `cert.pem`, `key.pem`, `role` | удостоверение агента и его роль (0600) |
| `agent.sock` | местная дверь (0600) |
| `savings.json` | счёт сэкономленного карточками; Сёма показывает его на экране агента |
| `state.json` | номер последнего показанного уведомления: пропущенное за сон добирается само |
| `agent.log` | журнал под launchd; на Linux — `journalctl --user -u semaagent` |
| `tools/` | собранный помощник на Swift |

### Тесты

```sh
go test ./... -count=1
```

`deploy_test.go` сверяет флаги в файлах службы с флагами агента:
переименованный флаг иначе сломал бы службу молча, и узналось бы это после
перезагрузки машины.
