# Память Сёмы и понимание кода для агентов на этом маке

Одна дверь на всё: **житель машины** (`semaagent`). Он держит языковые
серверы, отдаёт карточки кода и он же спрашивает у Сёмы память — своим
шифрованным проводом (TLS со взаимной проверкой, сертификат выдала сама
Сёма). Ни адреса, ни токена в настройках агентов разработки не остаётся.

Раньше память жила за сетевой ручкой Сёмы, а Сёма живёт в контейнере и
пересоздаётся при каждом выкате: сессия MCP умирала вместе с ним, и
посреди работы память отвечала «нет связи». Житель машины стоит под
launchd, переживает выкаты и уже опознан — поэтому дверью стал он.

Новый агент появляется на экране «Память» без областей и ждёт выдачи: до
этого на все обращения отказ. Способность «память» человек включает на
экране «Агенты» — она тоже появляется выключенной.

## Житель машины

    cd ~/repo/semaagent && go install ./cmd/semaagent
    semaagent -enroll <код приглашения от Сёмы>   # разово, за удостоверением
    semaagent -link sema.local:8766               # демон: провод к Сёме

Демон открывает местную дверь — сокет `~/.sema-agent/agent.sock` (права
0600). Через неё ходят обёртки агентов разработки и хуки памяти: порт с
токеном для этого больше не нужен. Под launchd демон стартует сам
(`~/Library/LaunchAgents/org.example.semaagent.plist`).

Клиенты подключаются тем же бинарником — он видит живого демона и
работает тонкой обёрткой, поэтому языковой сервер поднимается один раз на
всех:

    # Claude Code — в ~/.claude.json, mcpServers.sema-agent
    command: ~/go/bin/semaagent

    # Codex — в ~/.codex/config.toml
    [mcp_servers.sema_agent]
    command = "/path/to/semaagent"

Инструментов двенадцать. Код: `symbols` (оглавление файла), `context`
(карточка символа), `impact` (радиус поражения перед правкой),
`definition`, `diagnostics` (что сломано сейчас, без сборки; можно
передать `text` — тогда проверяется код, которого нет на диске),
`search`, `agent_status`. Память: `memory_session_start`,
`memory_session_end`, `memory_recall`, `memory_remember`,
`code_knowledge`.

Рабочая папка едет в каждом запросе к памяти: житель машины один, а
проектов много, и области выданы паре «агент разработки плюс папка».
Обёртка подставляет её сама — корень git-репозитория, а если у родителя
лежит `CLAUDE.md` и сам он не под git, то родитель: зонтик из нескольких
репозиториев это один проект, а не три.

Языки берутся из справочника по расширению файла: Go, Rust, Swift,
TypeScript/JavaScript, Python, Vue. Нет языкового сервера — ответ
приходит ярусом ниже с честной пометкой, а не отказом.

## Claude Code

Хуки: скопируйте `hooks` из `claude-code/settings.example.json` в
`~/.claude/settings.json` (или в `.claude/settings.json` проекта).
`SessionStart` кладёт в контекст уроки, факты и кристалл прошлой сессии
проекта (возобновление продолжает ту же сессию); `Stop` дописывает
последний обмен репликами в сводку; `SubagentStop` дописывает итог
субагента — иначе работа целого агента идёт мимо памяти; `SessionEnd`
закрывает сессию, кристалл и факты делает роль «Память». Сессии видны на
экране «Память → Сессии».

Каждый хук — одна строка: вызов `semaagent -hook <вид>`. Разбор события,
поиск корня проекта и разговор с Сёмой живут в бинарнике, а не в скрипте.

## Codex

    codex features enable hooks           # флаг hooks в ~/.codex/config.toml
    # хуки лежат в ~/.codex/hooks.json (в корне ~/.codex; до 0.153 — в ~/.codex/hooks/)
    # возьмите codex/hooks.example.json и поправьте пути

События те же. Ответ хука `SessionStart` Codex ждёт в виде JSON
(`hookSpecificOutput.additionalContext`) — его печатает сам житель
машины. `UserPromptSubmit` дописывает реплику человека, `Stop` — ответ
агента: Codex отдаёт его прямо в хук, стенограмму разбирать не нужно.

**После любой правки `hooks.json` — `/hooks` в консольном Codex и
«trust»**: с версии 0.153 доверие к хуку записывается по его хэшу, и
изменённый хук молча пропускается, пока его не доверили. Ни ошибки, ни
строки в журнале — только пропавшие сессии в памяти Сёмы.

Разовый `codex exec` хуков не зовёт вовсе, и работа пропадала мимо
памяти. Для него есть обёртка: `codex/exec.sh «задание» [папка]` — сама
открывает сессию, подмешивает память проекта в задание, кладёт ответ
заметкой и закрывает сессию даже при неудаче.

Проверка: `codex exec "привет"` в любом проекте, потом экран
«Память → Сессии» — там появится сессия «Codex · …».

## Когда связи нет

Житель машины не поднялся — инструменты памяти отвечают ошибкой про
связь, а не пустотой: пустой ответ агент разработки прочитает как «в
памяти ничего нет» и запишет неверный вывод. Хук в этом случае молчит и
завершается с нулевым кодом: сессия агента разработки не должна падать
из-за памяти.

Выкат Сёмы посреди работы не виден: провод рвётся, житель машины
перезванивает и повторяет вопрос сам. Пропажу самого жителя машины Сёма
показывает уведомлением «Агент пропал со связи» — оно закрывается само,
когда он вернулся, и говорит, сколько связи не было.

## Guardrails

Всё входящее проходит маски секретов (экран «Память» → Правила): строки с
токенами и ключами отбрасываются, попытка попадает в журнал. Облачной
модели уходят только области с тумблером «наружу».

## Пути

Скрипты живут здесь, в репозитории агента. Хуки прописываются полным
путём, поэтому после переезда папки их надо поправить в двух местах:
`~/.claude/settings.json` (команды хуков) и `~/.codex/hooks/hooks.json`.
Признак, что забыли: `Stop hook error: No such file or directory`.

### Codex и подтверждения

В неинтерактивном `codex exec` вызовы MCP по умолчанию отклоняются:
`MCP tool call requires approval, but approval policy is never`. Запускать
надо с `--approve-for-me` (он несовместим с `--sandbox`, песочницу выбирает
сам). Настройка `default_tools_approval_mode` у сервера этого не заменяет:
она принимает `auto | prompt | writes | approve`, но общая политика в
`exec` всё равно перекрывает её.
